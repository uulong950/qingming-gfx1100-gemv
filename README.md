# qingming-gfx1100-gemv

**A native FP32 GEMV for AMD RDNA 3.**

`qingming-gfx1100-gemv` is a high-performance FP32 GEMV implementation for `gfx1100`, built and validated on the Radeon RX 7900 XTX.

It combines shape-aware kernels, K-space parallelism, persistent execution, and compensated FP32 reduction stitching to push bandwidth-bound GEMV without giving up numerical quality.

On our validated benchmark suite, it beats **rocBLAS on 461 / 461 executable shapes** and **hipBLASLt on 435 / 435 mutual-PASS shapes**.

## What is different

GEMV is usually memory-bound. The hard part is not adding more FLOPs — it is keeping the GPU busy across very different matrix shapes.

This implementation uses a small set of shape-driven execution strategies:

- compact kernels for small `N`
- packed and multi-row kernels for narrow matrices
- row and streaming kernels for bandwidth-bound regions
- split-K execution when output parallelism is too low
- GRID_SPLIT for long reductions with small `M`
- persistent-register kernels where repeated launch structure is beneficial

The dispatcher selects the execution path from `(M, N)`.

For GRID_SPLIT, partial reductions are completed inside the final workgroup. The stitching stage uses compensated FP32 summation while the main dot product remains FP32/FMA.

## Numerical behavior

Performance is only half of the project.

The repository also includes a numerical suite for long FP32 reductions, using a host FP64 reference built from the exact FP32 operands.

It covers:

- positive and signed inputs
- adjacent cancellation
- block cancellation
- multiscale cancellation
- cancellation-distance tomography
- adaptive breakpoint zoom
- repeated-run determinism
- hipBLASLt solution-index comparison

The native implementation passes the full benchmark correctness suite and remains in the same numerical-quality regime as rocBLAS on the tested long-reduction workloads.

The numerical experiments also expose reproducible reduction-order-sensitive behavior in hipBLASLt on selected long reductions.

These observations are scoped to the tested hardware, ROCm version, shapes, inputs, and tolerances. Numerical breakpoints constrain effective reduction ordering; they do not by themselves prove an exact physical wavefront, LDS boundary, or reduction tree.

## API

```cpp
extern "C" hipError_t gemv(
    const float* A,
    const float* x,
    float* y,
    std::int64_t m,
    std::int64_t n,
    std::int64_t lda,
    void* workspace,
    hipStream_t stream);

extern "C" std::uint64_t gemv_workspace_bytes(
    std::int64_t m,
    std::int64_t n);

extern "C" const char* gemv_path_name(
    std::int64_t m,
    std::int64_t n);
```

If `gemv_workspace_bytes(m, n)` returns a non-zero value, the caller must provide at least that many bytes of workspace and keep it valid until the GEMV launch completes.

## Scope

This project is intentionally narrow.

It targets native FP32 GEMV on `gfx1100`, with the Radeon RX 7900 XTX as the validated device.

The published performance and numerical results describe this tested configuration. They should not be interpreted as universal claims about rocBLAS, hipBLASLt, other ROCm releases, other GPUs, or general GEMM workloads.
